## Compatibility

| सतह | स्थिति |
|---|---|
| DSH डेस्कटॉप / वेब क्लाइंट | 0.2.x |
| Node.js | ≥ 20 |
| होस्ट सोर्स में बदलाव | कोई नहीं |

प्लगइन केवल `ctx.theme.overrideTokens` से रंग टोकन की एक परत जोड़ता है; यह नया थीम पंजीकृत नहीं करता, होस्ट को पैच नहीं करता और अपीयरेंस सेटिंग नहीं बदलता।

## What it does

- **4 पैलेट** — मोनो, वार्म सैंड, इंडिगो, मॉस — हर एक लाइट और डार्क दोनों के लिए अलग से अनुकूलित;
- पूरी रैंप **दोबारा गणना** होती है, बदली नहीं जाती: OKLCH पुनर्निर्माण → भूमिका-आधारित क्रोमा → **sRGB गैमट क्लैंप** → वास्तविक सतहों पर कंट्रास्ट हल;
- 27,000+ टोकन संदर्भ शामिल: मुख्य टेक्स्ट, द्वितीयक, तृतीयक, कैप्शन, लिंक, साइडबार, कार्ड, उपयोगकर्ता बबल, प्राइमरी बटन, स्क्रॉलबार, स्विच, Markdown शीर्षक/बोल्ड, कोड ब्लॉक;
- समायोज्य: टेक्स्ट की तीव्रता (3), साइडबार की गहराई (3), दायाँ पैनल (2), Markdown ज़ोर, स्क्रॉलबार, स्विच का रंग;
- **स्व-उपचार**: यदि होस्ट ओवरराइड परत हटा दे, पैलेट फिर से लगा दी जाती है;
- इंटरफ़ेस 简体中文 / 繁體中文 / English / 日本語 में (होस्ट की भाषा का पालन करता है, हाथ से भी चुना जा सकता है)।

## Install

```bash
# npm से
cd ~/.dsh/profiles/desktop
pnpm add dsh-theme-palette

# या कोई विशेष संस्करण
pnpm add dsh-theme-palette@1.4.3
```

GitHub रिलीज़ के tarball से:

```bash
pnpm add "https://github.com/zuoyunlai/dsh-theme-palette/releases/download/v1.4.3/dsh-theme-palette-1.4.3.tgz"
```

इसके बाद **GUI को फिर से शुरू करें** — चल रहा प्रोसेस पुराना मॉड्यूल रखता है। खोलें: अवतार → सेटिंग्स → **Color theme**।

## Configuration

| विकल्प | विकल्प |
|---|---|
| पैलेट | मोनो · वार्म सैंड · इंडिगो · मॉस (थंबनेल लाइट/डार्क का पालन करते हैं) |
| तीव्रता | शांत / मानक / गहरा — टेक्स्ट पैलेट का कितना पालन करे |
| सतहें | साइडबार (हल्का / समान / गहरा), दायाँ पैनल (साइडबार जैसा / कैनवास जैसा) |
| और विकल्प | भाषा, Markdown ज़ोर, स्क्रॉलबार, स्विच/चेक |

हर चुनाव तुरंत लागू होता है और `localStorage` में सहेजा जाता है। लाइट/डार्क होस्ट की «अपीयरेंस» सेटिंग में ही रहता है।

## Palette engine

```
OKLCH(L, C, ह्यू) ──► गैमट क्लैंप (C पर बाइनरी खोज) ──► sRGB हेक्स
        ▲
        └── भूमिका क्रोमा × तीव्रता, फिर {कैनवास, कार्ड, साइडबार, ओवरले} पर कंट्रास्ट
```

- सेमांटिक एलियस `var(--dsw-static-neutral-bluish-NN)` श्रृंखलाएँ बनाए रखते हैं, इसलिए जो भी टोकन का पालन करता है वह पैलेट का भी करता है;
- लाइट सतहें स्टेप 00–300, डार्क सतहें 800–950;
- टेक्स्ट की न्यूनतम सीमा बनाते समय लागू: मुख्य ≥ 12, द्वितीयक ≥ 6.1, तृतीयक/लिंक ≥ 4.6, साइडबार में ≥ 7, बबल में ≥ 7;
- `node palette-dev.mjs` 432 संयोजन जाँचता है।

डिज़ाइन नोट्स, घटक-वार तर्क और कंट्रास्ट तालिकाएँ [docs/DESIGN.md](docs/DESIGN.md) में। इतिहास: [CHANGELOG.md](CHANGELOG.md)।

## Development

```bash
node palette-dev.mjs                  # सभी पैलेट का टोकन रिपोर्ट
node tools/sheet.mjs                  # पैलेट बोर्ड → tools/sheet.html
node tools/shoot-sheet.mjs            # बोर्ड का स्क्रीनशॉट (हेडलेस Chrome)
node tools/compare.mjs --dir tools/out/<run>        # बेसलाइन से तुलना
node tools/preview-settings.mjs --lang en           # सेटिंग्स पेज रेंडर करें
node tools/release.mjs --dry          # रिलीज़ प्रीफ़्लाइट
node tools/release.mjs --tag          # npm पर प्रकाशित + टैग
```

स्क्रीनशॉट रिग्रेशन की दो परतें हैं: पैलेट बोर्ड (बिना लॉगिन) और CDP से असली डेस्कटॉप विंडो (`tools/shoot-desktop.mjs`, `--remote-debugging-port` चाहिए)। देखें [tools/README.md](tools/README.md)।


## Pitfalls we hit

1.7.0 ऑडिट में सबसे चौंकाने वाली पाँच बातें — हर एक टेस्ट से निकली, स्क्रीनशॉट देखकर नहीं।

- **सफ़ेद एक्सेंट से सफ़ेद लिंक बनता था** (1.13:1)। कॉन्ट्रास्ट सॉल्वर केवल एक ही दिशा में चलता था — बैकग्राउंड से दूर — इसलिए बैकग्राउंड से हल्का एक्सेंट सफ़ेद की ओर ही बढ़ता गया।
- **रंग बदलने पर पेज बदला, पैनल नहीं।** कंपोनेंट पैलेट id पर सब्सक्राइब था, जो रंग बदलने पर नहीं बदलता; React ने स्नैपशॉट की तुलना की, अंतर न मिला, और री-रेंडर छोड़ दिया।
- **कॉन्फ़िगरेशन साझा हुआ, रंग नहीं।** शॉर्ट कोड में मोड्स तो थे पर तीन कस्टम रंग नहीं, इसलिए दूसरी मशीन पर इम्पोर्ट सफल बताता और स्थानीय मान रख लेता था।
- **गहरे मॉड्यूल सतहों की एक सीमा है।** सबसे गहरी सतह पर शुद्ध सफ़ेद भी केवल ~10.99:1 तक पहुँचता है, इसलिए 10:1 (उच्च-कंट्रास्ट 15:1) वहाँ भौतिक रूप से असंभव है। अब हम उस सतह की अधिकतम प्राप्य सीमा तक समायोजित करके "सतह-सीमित" चिह्नित करते हैं।
- **एक चयनकर्ता जिसे हम मृत समझते थे, वह जीवित था।** ऑडिट ने शुरू में उसे टूटा बताया; शिप की गई CSS के विरुद्ध कॉन्ट्रैक्ट टेस्ट ने विपरीत साबित किया। गलती निष्कर्ष में थी, कोड में नहीं।

## Trade-offs

यहाँ के अन्य थीम प्लगइन ग्लास, वॉलपेपर और एनिमेशन देते हैं। हम जानबूझकर नहीं करते:

- **न ग्लास, न वॉलपेपर।** वे स्क्रीनशॉट से जीतते हैं; हम प्रमाण से जीतना चाहते हैं।
- **न थीम मार्केट, न AI रंग सृजन।** दोनों ऐसे रंग लाते हैं जिन्हें हम गारंटी नहीं दे सकते; कॉन्ट्रास्ट सॉल्वर ही संपत्ति है।
- **और पैलेट नहीं।** चार प्रीसेट + तीन-रंग जनरेटर, हाथ से चुने दस से बेहतर है; मात्रा बढ़ाना फ़ायदा नहीं।
- **न आँखों की सुरक्षा के वादे।** हम उसी सतह पर मापे अनुपात बताते हैं जहाँ टेक्स्ट वास्तव में बैठता है, और जहाँ यही ऊपरी सीमा हो वहाँ "सतह-सीमित" कहते हैं।
