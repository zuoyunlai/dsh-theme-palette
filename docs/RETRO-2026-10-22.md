## ② 问题台账

### P0-1 装入 1.4.1 后启动崩溃，整个 profile 插件全不加载

- **现象**：重启报 `startup failed: 1 required plugin did not activate`，失败项 `modules`，错误 `client-modules: dsh-theme-palette declares dsh.client but exports no "./client" bundle`；界面所有插件消失。
- **根因**：1.4.1 为补展示元数据加了 `exports`，只写了 `.`、`./locale/*.json`、`./icon`，**漏 `"./client"`**。`client-modules` 取不到就抛错，而 `modules` 是 required 插件 → 全量不加载。
- **处置**：1.4.2 补齐 8 个子路径；对 profile 内**全部 22 个**声明 `dsh.client` 的包做同类扫描（全部可解析）。
- **防复发**：`tools/release.mjs` 断言 `exports["./client"]` 存在且文件可读 → 见 `WORKFLOW-NOTES.md §2`。
- **教训**：官方 check 不校验这条，当时 12 项全绿。

### P0-2 profile 插件清单被写成 2 条（28 → 2）—— **已核查：一次性，未复发**

- **现象**：`~/.dsh/profiles/desktop/package.json` 的 `dsh.profile.bundles` 只剩 `dsh-base` / `dsh-web-app`；包全在 node_modules。
- **核查结论（2026-10-22 15:40 实测）**：
  1. 恢复后到现在的**崩溃日志共 10 份，全部是同一条** `desktop welcome: Web authentication failed`（03:32–03:56Z），**没有一份**是 `modules` / `exports` 那类装配失败 → 1.4.2 之后的启动装配是干净的；
  2. 当前 bundles = **27**，与恢复时的 28 相比：少 `@local/dsh-pet` / `@michengai/dsh-btw` / `@hyzyn/dsh-rss`，多 `dsh-pet-plugin` / `@dshworks/dsh-solidworks` —— 这些是**你自己换插件**的编辑，不是塌缩；
  3. 两个 profile 的 bundles 都仍含 `dsh-theme-palette`。
- **定性**：塌缩发生在"启动失败"那一个窗口里，属一次性副作用；恢复后经过多次启动未再发生。
- **处置**：已从备份恢复；备份文件保留在 `~/.dsh/_backup/profile-package-2026-10-21.restored.json`。
- **防复发**：改 profile 前先备份、改完核对数量（`WORKFLOW-NOTES.md §3`）——不需要额外的守护脚本。
- **教训**：用户看到"插件都没了"时，真实含义通常是**清单丢了**，不是包丢了。

### P0-3 另一类独立崩溃：`desktop welcome: Web authentication failed`（未闭合）

- **现象**：2026-10-22 03:32–03:56Z 共 10 次启动失败，错误 `Error: desktop welcome: Web authentication failed`（`lib/main.js:8886 connectDesktopWelcome`）。
- **与本插件的关系**：**无关**——它发生在桌面壳与自身 web 服务握手的鉴权环节，早于任何插件加载；同一时间窗内插件组成（bundles）是完好的。
- **可能原因（待你确认）**：那段时间正在新建 `web` profile 并反复启动，桌面壳连到的 web 服务地址/token 不匹配。
- **影响**：启动直接失败，看不到界面；与配色无关。
- **状态**：**开放**。若再出现，检查是否有多个 DSH 实例/端口占用，以及 `~/.dsh` 下当前 profile 的 web 服务地址。

### P2-1 文档承诺了跑不起来的回归层

- **现象**：`tools/README.md` 写桌面真机截图回归可用；实际 `shoot-desktop.mjs` 的 `ready` 必然失败。
- **根因**：脚本依赖 `window.__DSH_THEME_PALETTE_DEV__` 的 `attach`，**全仓无任何地方创建这个全局**（只在测试桩里定义）。
- **处置**：文档如实降级；**修复列在 A-5，未完成**。
- **教训**：写进文档 ≠ 存在 → `WORKFLOW-NOTES.md §8`。

## ⑤ 结论

- 这一轮把插件从"能跑"做到"有工程约束"：432 组合零违规、门禁 12/12、发版链有兼容性与导出预检、安全审计整改完毕。
- 代价是一次 P0（`exports`）与一次环境事故（清单塌缩），两者都**不是配色算法问题，而是"边界与装配"问题**——正是客户端插件最容易翻车的地方。
- 当前最大短板不是代码，而是**没有用户反馈、没有可见度、可编辑性弱于竞品**。下一步按 A-1 → A-2 → A-3 推进，而不是继续调色。
