# dsh-theme-palette

DSH Web / Desktop 的主题配色插件：**4 套配色 × 明暗两模式**，两个轴互相独立。

入口：左下角头像 → **设置** → 左侧导航「**主题色**」→ 四张卡片（黑白 · 暖砂 · 靛蓝 · 苔绿）+ 一行「左侧栏底色」。
选择即时生效，存在 `localStorage`。

当前版本 **0.8.2**（0.8.1 按深色专项审计重做深色侧，0.8.2 把强调色换成设计稿标准值；见 §修订记录）。

## 为什么配色会自己跳回默认（v1.3.1）

现象：设了暖砂，用了一阵（跑模型操作、切窗口、长时间放着），**突然变成黑白**，但设置页里
「暖砂」还是选中的。原因在宿主的 override 生命周期：

```js
// ThemeRuntime（宿主）
overrideTokens(source, tokens) {
  const layer = { seq: this.overrideSeq++, tokens: validateOverrides(source, tokens) }
  this.overrides.set(source, layer)
  this.publish()
  return () => { if (this.overrides.get(source) !== layer) return; this.overrides.delete(source); this.publish() }
}
```

而插件侧拿到的是被 runner 包装过的版本 —— **每一层的 disposer 都被挂在调用方的 fiber 上**：

```js
const dispose = Reflect.apply(method, target, [id, tokens])
ctx.effect(() => dispose, 'cordis-client-runner: dynamic theme override layer')
```

也就是说：**这一层的生命周期 = 插件 fiber 的生命周期**。插件被卸载/重载、或 fiber 的
effect 被清理时，层就没了；`composeActive` 在 `overrides.size === 0` 时直接返回内置主题，
于是页面**静默**变回默认色 —— localStorage 里的选择还在，设置页自然还显示暖砂。

会触发 fiber 重载的典型情况：动态插件被宿主重载（改过插件文件/profile、宿主自我更新）、
渲染进程恢复、以及某些"模型操作"引起的插件重载。

**v1.3.1 的处理**：加了一个自愈环。窗口重新可见 / 获焦 / `pageshow` / `theme/change` /
每 4 秒，回读 `body` 上的 5 个关键 token；不在了就把最后一层重放：

```
[dsh-theme-palette] 配色层不见了（visibility），已重放第 1 次
```

设置页顶部会显示"配色层被宿主丢过一次，已自动恢复 N 次"；健康时不产生任何写入。

**另一种可能**（值得先分辨）：如果是 **localStorage 被清**（换 profile、清缓存），设置页会回到
「黑白」选中态 —— 那种情况自愈救不回来，因为连"你想用哪套"都丢了。判据就是**设置页里选中的
是不是你原来那套**。

## 设置页重排（v1.3.0）

原来的设置页是六行"工程参数"堆在一起、每行都是同一种小药丸。v1.3.0 重做成四段：

```
主题色                                            v1.3.0
配色与明暗模式独立；切换后立即生效并保存在 localStorage。
┌────────────┬────────────┐
│ 缩略图      │ 缩略图   ✓  │   2×2 卡片：每张是「侧栏 + 画布 + 两行文字 + 强调色」的微缩图
│ 黑白 无色调 │ 暖砂 米白+棕 │
└────────────┴────────────┘
强度      正文与强调的着色程度        [静][标准][浓]
左侧栏底色 相对会话区的层次           [更浅][同色][更深]
右侧栏底色 面板底色                   [同左栏][跟随画布]
▸ 更多选项
```

四个变化：

1. **卡片有缩略图**，而且**跟随明暗模式**（深色下缩略图自动用深色画布/侧栏/强调色 —— 靠
   `body[data-ds-dark-theme]` 切换两组 CSS 变量，不是靠 JS 猜模式）；
2. **段落式行**：左边标题 + 副标题，右边分段控件，中间一条 0.5px 分隔线；
3. **分段控件**（segmented）替代散落的药丸，选中项是"抬起"的白色/深色片；
4. 标题右侧有版本徽标；样式表是**独立注入的一条 CSS**（`data-plugin-css=.../settings.css`），
   不再全是内联样式 —— 于是能写 `:hover`、媒体查询（窄屏单列）和 `body[data-ds-dark-theme]` 作用域。

### 怎么"看见"它

设置页在 App 里，外部浏览器进不去；但组件树可以脱离 React 渲染成静态 HTML：

```bash
node tools/preview-settings.mjs     # → tools/preview-light.html / preview-dark.html
node tools/shoot-html.mjs --file preview-light.html --out tools/out/settings
node tools/shoot-html.mjs --file preview-dark.html  --out tools/out/settings
```

`preview-settings.mjs` 用生产引擎算 token、用插件真正注入的 `SETTINGS_CSS`，
再用一个 20 行的树→HTML 渲染器把组件铺开 —— 所以截图就是"设置页长什么样"，
不是另画一版。

## 代码块底色（v1.2.0）

宿主的代码块底色是 `--dsw-alias-bg-layer-1`，而**浅色模式下 layer-1 就是画布色（都指色阶 00）** ——
所以代码框和正文底是同一块，只剩一条发丝线。v1.2.0 给它一档独立的"内嵌面板"色：

| token | 暖砂 | 与画布 ΔE | 代码文字对比 |
|---|---|---|---|
| `--dsh-code-fill`（围栏代码块） | `#eadcc7` / `#3e342d` | **5.52 / 11.05** | 5.75 / 8.04 |
| `--dsh-code-inline`（行内 `code`） | 更浅一档（色阶 50 打底） | ~5.9 | — |

规则同样注入到 `<head>`：

```css
[class*="_markdown_"] .md-code-block{background:var(--dsh-code-fill,inherit)}
[class*="_markdown_"] :not(pre) > code{background:var(--dsh-code-inline,inherit)}
```

`.md-code-block` 是宿主自己的类（不是 CSS Modules 哈希），特异性 0,2,0 高于宿主的 `.block`（0,1,0），
**不需要 `!important`**。`:not(pre) > code` 把围栏块里的 `code` 排除掉，只染行内代码。

## Markdown 标题与加粗（v1.1.0）

宿主的 Markdown 里，标题和正文**同色**（都继承 `label-primary`），只靠字号/字重区分。
v1.1.0 起把「标题」和「加粗」各染一档配色：

| token | 暖砂 | 对比度（画布 / 卡层） |
|---|---|---|
| `--dsh-md-heading` | `#42250b`（浅）/ `#fed9bd`（深） | 12.3 / 11.3 |
| `--dsh-md-strong` | `#2f1b08` / `#ffe2cc` | 14.4 |

**加粗只加色度、不动明度** —— 一开始用"混到强调色"，结果加粗比正文更亮（浅色下反而更弱）；
改成只叠加色相后，加粗与正文同深、只是"更有色"。标题则再往中间推一点明度
（浅色提亮 0.065 / 深色压暗 0.030），配合更大的字号拉开层级。

规则注入到 `<head>`，用 CSS Modules 的局部名做钩子（`[class*="_markdown_"]`，比整串哈希耐版本）：

```css
[class*="_markdown_"] :where(h1,h2,h3,h4,h5,h6){color:var(--dsh-md-heading,inherit)}
[class*="_markdown_"] strong{color:var(--dsh-md-strong,inherit)}
```

「更多选项 → Markdown 强调 > 同正文」可以关掉（token 置 `inherit`，回到宿主原样）。
黑白配色不染（它没有色相可跟）。

## 主人气泡（v0.18.0）

用户消息的底色是 `--dsw-specific-bubble`，宿主指向 `deepseek-50` —— 也就是「品牌色的极浅底」。
我的强调色色度比宿主的品牌蓝高得多，浅端直接算出 **`#ffede0`（R 顶满 255）**，在暖砂下看着发粉发红。

v0.18.0 改成「强调色按比例混进画布」，气泡是**有色味的浅底**而不是一块彩色：

| | 气泡 | 与画布 ΔE | 文字对比 |
|---|---|---|---|
| 暖砂 | `#f2e5d1`（浅）/ `#362c24`（深） | 4.2 / 7.9 | 13.53 / 11.89 |
| 靛蓝 | `#dce5f5` / `#272f40` | 4.9 / 7.8 | 13.29 / 11.62 |
| 苔绿 | `#dde9dd` / `#2b342b` | 4.6 / 7.5 | 13.39 / 11.37 |

混合比例：浅色 11%、深色 13%（`mix(强调色, 画布)`）。ΔE 4–8 足以让气泡读成一块面，
又不会盖过正文。

v0.12 把三档从“不可见”提到“可感知”，但**默认档 ΔE 只有 2.77** —— 在 14px 的会话标题上仍然读作黑字。
v0.17.0 再标定一次，让默认档真正看得出配色：

| 档位 | scale / lift | 暖砂标题 | ΔE | 正文对比 |
|---|---|---|---|---|
| 中性 | 1 / 0 | `#12110f` | 0 | 17.2 |
| **跟随（默认）** | 3.0 / +0.055 | **`#201d17`** | **5.5** | 15.3 |
| 浓一些 | 4.6 / +0.085 | `#28241a` | 8.5 | 14.1 |

靛蓝跟随是 `#1b1d23`（ΔE 5.4）、苔绿 `#191f1b`（ΔE 5.6）。
深色正文同步加深：暖砂 `#f3efe5` → `#f9efd6` → `#feeeca`（ΔE 2.1 / 3.6）。

仍远高于 AAA 的 7。**如果想要纯黑**，切「中性」即可。

## 注释 / 说明文字（v0.16.0）

DSH 里“注释类”文字走的是 `--dsw-alias-label-caption`：宿主浅色指色阶 **400**、深色指 **600**。
它落在 `mid` 角色上，原来只给 0.006 的色度 —— 等于灰字。v0.16.0 两件事：

**① 跟着「文字着色」走（部分强度）**。`mid` 角色（注释 400/600、三级、`label-dimmed` 200）
乘 `1 + (textScale-1) × 2.0`，并且 `midC` 从 0.006 提到 0.010：

| 档位 | 暖砂注释 | ΔE | 靛蓝 / 苔绿注释 |
|---|---|---|---|
| 中性 | `#b3b1ad` | 0 | `#afb1b6` / `#aeb3af` |
| 跟随 | `#b8b1a1` | 1.76 | `#abb2c1` / `#a7b6aa` |
| 浓一些 | `#bdb194` | 3.61 | `#a5b2cd` / `#9ebaa5` |

注释刻意比正文弱一档（正文 跟随 ≈2.8、浓一些 ≈6.4），否则整页都会“彩色化”。

**② 修掉深色注释的对比度**。宿主深色注释用 600，而这个步为了「浅色三级文字达标」被求解压暗过，
在深底上只剩 **3.0:1**。深色这一侧改用 500 → **6.0–6.3:1**；浅色保持宿主原值
（宿主自己的浅色注释就是 1.95，那是它的低对比设计，要提亮我可以换 500）。

## 设置页的两条约定（v0.15.0）

**① 选中卡片用 token，不用内联色。** 之前选中项的淡底是「强调色 8% 混**浅色**画布」写成内联样式的，
深色模式下就变成一张近白卡片，而卡片文字是 `label-primary`（深色下近白）—— 白底白字。
现在由 token 层给 `--dsh-card-picked` 一对值：

| | 选中底色 | 卡片文字对比 |
|---|---|---|
| 暖砂 浅 / 深 | `#f3e6d3` / `#3b3028` | 14.55 / 11.17 |
| 靛蓝 浅 / 深 | `#dde7f6` / `#2a3345` | 14.25 / 11.00 |
| 苔绿 浅 / 深 | `#deebdf` / `#2f392f` | 14.42 / 10.55 |

**② 细项默认折叠。** 配色卡片下面是「▸ 更多选项」；文字着色 / 左侧栏 / 右侧栏 / 滚动条 /
开关勾选这五行只在展开后出现。所有档位都保留，默认值就是我推荐的那套，不展开也能正常用。

## 1.0.0：按设计审计重做的四件事

**① 色域安全钳位。** `fromOklch` 现在先判断是否超出 sRGB（线性通道必须落在 [0,1]），
超了就二分收色度，而不是把通道硬钳到 0/255。此前「暖砂气泡算出 `#ffede0`、R 恒为 255」
就是这个缺口的症状 —— 颜色会被压成另一个色相。

> 顺带更正审计里的一个数字：我第一次测「占色域 %」只判断了负通道（漏了超 1 的情况），
> 所以报成 3–12%。真实值是 暖砂 62% / 靛蓝 **99%** / 苔绿 26% —— 靛蓝不是"没上色"，
> 而是**顶到高明度的蓝色上限还超了一点**（14.8‰ 请求 vs 14.1‰ 上限）。

**② 浅色侧重标定。** 近白端整段下移 0.044（画布 0.968 → 0.955），高明度处色域上限因此抬高
（蓝色在 L 0.97 只有 14‰、L 0.95 有 24‰）；`lightC` 上调到 0.030 / 0.020 / 0.016；
暖砂浅底色相 88→84、强调 52→60（收敛到 ±20° 内）；苔绿 152→162 与暖砂拉开。

套间区分度（浅画布 ΔE）：暖砂↔苔绿 **2.15 → 3.07**、暖砂↔靛蓝 3.84 → 5.04、靛蓝↔苔绿 2.28 → 2.85。

**③ 黑白配色也过引擎。** 它色度全 0（保持宿主原貌），但走 `tuneRamps` 求解：
三级文字 3.42 → **4.67**、链接 3.91 → **4.63**（都到 AA 了），主按钮顺带压暗到 4.54。

**④ 信息架构从 6 行参数改成 3 段。**
配色卡片 → **强度**（静 / 标准 / 浓）→ **面板表面**（侧栏三档 + 右栏两档）→ **▸ 更多选项**（滚动条、控件）。
「文字着色」改名为「强度」并升为主控件；旧的「跟随 / 浓一些」是相对量，现在是一档风格。

**⑤ 运行时自检。** 应用后回读 `body` 上的 5 个关键 token，写不进去就在设置页显示
「⚠ 部分 token 未生效」并在控制台告警 —— 宿主改 token 名时不再静默失效。

## 挂在哪一层

注册 **`settings.section`**（设置侧栏独立一节）。官方内置节顺序 account -10 / general 0 / models 10 /
plugins 15 / agent-presets 20，本插件 `order: 5`，紧跟「通用」之后。页面自己画标题（`h2` 18px/600），
与官方 `AgentPresetSection` 一致 —— `settings.section` 只渲染侧栏条目（文字取 `label()`），不渲染内容标题。

## 配色怎么算

1. **OKLCH 重建色阶**：保留每一步的感知亮度，只换色相与色度。
2. **色度按 UI 角色给**：浅色底 0.013–0.024、中间灰 0.006、浅色正文 0.004、
   深色层 0.014–0.028、深色正文 0.009–0.014。正文只给极低色度以保证字形锐利。
   **深色层的色度必须按色相分别给**，不能三套共用一个数：绝对色度不决定观感，占比才决定 ——
   L 0.23 处可用色域是暖砂 0.048 / 苔绿 0.061 / 靛蓝 0.157，同一个 0.016 会得到
   35% / 23% / 11% 三种相对饱和度（暖砂发脏、靛蓝发灰）。现在三套分别落在 30% / 24% / 19%。
   深色层的色度权重也**不随明度递减**（`800/850/875` = 1.0 / 1.0 / 0.95）：层与层之间只靠明度分层，
   权重递减会让卡片/模块比画布灰 30–45%，读作「换了一种材质」。
3. **近白端等量下移 0.032**（`L ≥ 0.92`）：不是压缩斜率。压缩会把「画布↔卡层」的 ΔL
   从 0.031 压到 0.0147，而 `L<0.92` 那段又没压，明度节奏会在边界处断层。
4. **对比度求解到真实承载面**：三级文字与链接大量落在卡层 `60`、悬浮层 `150`、深模块 `800` 上，
   所以靶点用这些面而不是画布；上限 ±0.13（从 4.41 抬到 4.62 需要 ΔL≈0.096）。

覆盖 **75 个 token / 套**：4 条静态色阶（19+16+10+12）+ 14 个**字面量**别名
（边框 `border-l1..l4`、`bg-skeleton`、`menu-group-surface`、`interactive-bg-hover/-active/-hover-accent`、
`button-tool-bar-*`、`bg-mask-drop` 等）+ 3 个侧栏 token。

## 对比度（按真实承载面实测）

暖砂一行为例（三套同构，差在 0.01 量级）：

| 承载面 | 底 | 主文本 | 次文本 | 三级 | 链接 |
|---|---|---|---|---|---|
| 画布 `00` | `#fbf4e3` | 17.23 | 6.78 | 5.02 | 5.57 |
| 卡层 `60` | `#f2ebdb` | 15.90 | 6.26 | 4.63 | 5.14 |
| 深画布 `950` | `#1e1b14` | 14.98 | 11.39 | 8.02 | 7.36 |
| 深层1 `875` | `#2c2922` | 12.65 | 9.62 | 6.77 | 6.22 |
| 深卡 `850` | `#36332b` | 10.99 | 8.36 | 5.89 | 5.40 |
| 深模块 `800` | `#403c35` | 9.56 | 7.27 | 5.12 | 4.70 |

链接列取 `--dsw-alias-link`（从基准色派生出来的那一档），**不是**色阶中段 `500` ——
见 §品牌基准色与链接。

`875 / 850 / 800` 分别是宿主的 `bg-layer-1 / -2 / -3`（`bg-module-platform` 与 layer-3 同为 `800`），
所以深色的三级文字与链接要按**最亮的那个面**（`800`）兜底，而不是按画布。

**承诺范围**：`00 / 60 / 800 / 850 / 875 / 950` 全部 ≥ AA（三级与链接 4.62 起），
正文在所有深色面上 ≥ 8.95（AAA 的 7 线有余量）。三套配色 **0 处低于下限**。

`palette-dev.mjs` 把「合规下限」与「设计目标」分开记：低于 WCAG 线打 `✗` 并计数，
只低于设计目标（深色正文 ≥ 10）打 `△`、不计违规。现在唯一带 `△` 的是 `800` 面的正文
（8.95–9.56）—— 那是「最亮的深色面 + 近白文字」的固有代价，不是还没修好的违规。
悬浮层 `150`（toast / tooltip / popover）**不在承诺内**：宿主在这些面上本来就用白字，
在参数上补偿会把强调色冲淡；需要时由宿主自己保证。

「强调」列是设计稿给的**基准色**（色阶 `500`），「深强调」是由它派生的深色侧强调（色阶 `400`）。

深底三套的明度**故意不同**（L 0.223 / 0.227 / 0.239）：低色度下色相换不来区分度，
三套原本都落在 0.230，结果暖砂↔苔绿在深色层上只差 ΔE 1.15（低于 JND 2，等于分不出）。
错开明度后最小一对是 2.05。

黑白走宿主原值（`#ffffff` / `#151517`），只叠侧栏档位 —— 它没有色调可继承。

## 品牌基准色与链接（v0.8.2）

强调色由三要素定，设计稿给的是**基准色**，对应色阶中段 `500`：

| 套 | 基准色 | rgb | OKLCH（L / C / h） | 白字对比 | 在浅色 `150` 上 |
|---|---|---|---|---|---|
| 暖砂 | `#a9683e` | 169, 104, 62 | 0.580 / 0.101 / 52.4° | 4.43 | 3.40 |
| 靛蓝 | `#3f66a3` | 63, 102, 163 | 0.511 / 0.107 / 259.0° | 5.77 | 4.41 |
| 苔绿 | `#4f7a42` | 79, 122, 66 | 0.534 / 0.096 / 138.7° | 5.01 | 3.84 |

`500` 这一档的明度**被定死在设计值**（`accentL` 直接给 L，不乘 `accentScale`）：宿主和本插件
都拿它当品牌面 —— `--dsw-alias-button-info-fill`、`--dsw-alias-state-business-primary`（焦点环）、
`label-deep-diving` 的混色基色、以及设置页每张卡片的预览色。所以它必须是设计稿那个数，
不能被求解器按承载面改写。

用 `accentScale` 也能把 500 压到设计明度，但那会连带把 `deepseek-50/100/200`（宿主的选中态软底）
整条压暗 13%，软底就不软了 —— 这是 `accentL` 单独存在的理由。

**但基准色不能当正文链接**（上表最后一列）：暖砂 3.40、苔绿 3.84 都低于 AA 4.62，靛蓝 4.41 也压线。
链接是当文字用的，所以 `--dsw-alias-link` 由基准色**派生**：同色相、同色度、明度往远处收到达标
（最多 0.13，与其它求解同一上限）。

| 套 | 链接（浅） | 对 `150` | 链接（深） | 对 `800` |
|---|---|---|---|---|
| 暖砂 | `#915227` | 4.68 | `#c8a28b` | 4.70 |
| 靛蓝 | `#3c629f` | 4.67 | `#95acd0` | 4.64 |
| 苔绿 | `#436d36` | 4.63 | `#9cb695` | 4.64 |

这是本插件唯一一条「不是标准值、而是从标准值派生」的颜色。所以报表里的 `link500` 读的是
`--dsw-alias-link`，不是 `--dsw-static-deepseek-500` —— 后者是基准色，界面上只当填充/焦点环用。

## 暖砂的「夜色」（v0.14.0）

暖砂的浅色色相是 **88°（黄）**。同一个色相搬到 L≈0.22 的暗部会读成**橄榄绿** ——
所以暗色模式看着“发绿、和米白不搭”。这不是彩度问题，是**色相在低明度下的读法问题**。

v0.14.0 起每套配色可以单独给「夜相」（`darkHue`）：暖砂深色层用 **60°（橙棕）**，
浅色侧仍是 88°（米白）；深端的 neutral（深色模式滚动条）也跟同一夜色相，避免一半棕一半橄榄。

| | 浅色画布 | 深色画布 | 层 2 | 层 3 |
|---|---|---|---|---|
| 改前 | `#fbf4e3` h88 | `#1e1b14` **h88（橄榄）** | `#36332b` h90 | `#403c35` h82 |
| 改后 | `#fbf4e3` h88 | `#201a14` **h62（咖啡）** | `#38312c` h58 | `#423b36` h58 |

靛蓝（266°）与苔绿（152°）在暗部本来就读得对，未改。

## 深色模式

深色这一侧是单独调过的，四件事：

1. **层与底错开明度**（`darkLift` 0.026 / 0.032 / 0.042）：让三套在深色下分得开，
   同时给每套一个可辨的「夜色」（暖砂更深、苔绿更亮）。
2. **色度按色相归一化**（`darkC` 0.014 / 0.028 / 0.015）：落在各自可用色域的 30% / 19% / 24%。
3. **层内色度恒定**（`ROLE` 深色权重 1.0 起）：卡片与模块不再比画布灰，
   层间只差明度（ΔE 5.9 / 3.9 / 3.7），像「同一材质的不同高度」。
4. **正文单独一条色度**（`paperC` 0.014 / 0.009 / 0.0125）：近白但不透亮，
   且不会顶到 8-bit 天花板（L 0.953 处蓝的可用色度只有 0.0235）。

正文对比度 14.40–14.98（宿主 17.45，提亮底色必然的代价，仍是 AAA 的两倍）。
深色下正文一律 ≥ 8.95（在 `800` 面上），三级 ≥ 4.79，链接 ≥ 4.65。

## 区块底色：左侧栏

`--dsw-specific-sidebar-fill` 内置是 `bluish-50/-900`，与画布几乎同色，左栏和会话区看不出边界。
本插件把它解耦，三档（默认「更深」）：

| 档位 | 浅色：画布↔侧栏 / 悬停 / 选中 | 深色：画布↔侧栏 / 悬停 / 选中 |
|---|---|---|
| 更浅 | 1.74–2.13 / 0.30–0.59 ⚠ / 0.90 | **4.66–5.05** / 2.85–3.08 / 5.94–6.03 |
| 同色 | 0 / 2.40 / 4.83 | 0 / 2.93–3.00 / 5.86–6.05 |
| **更深（默认）** | 2.06–2.10 / 2.42 / 4.85 | **4.03–4.30** / 2.97–3.12 / 5.99–6.09 |

深色侧原来沿用浅色步长（×0.6），画布↔侧栏只有 ΔE 1.9–2.3 —— 正好卡在 JND 上，于是「左栏和中栏
看不出界线」。v0.13.0 起深色模式用**独立的 `darkLift`**（0.048 / 0 / −0.042），三套配色在深色下都到
ΔE 4 以上；侧栏内正文对比 12.48–16.40，仍满足 AAA。

ΔE 为 OKLab 欧氏距离 ×100，并排大色块的 JND ≈ 2。

**默认给「更深」是因为几何**：侧栏在画布之上时，悬停/选中只能往下走，两档就会穿过画布
（选中项像在页面里挖了个洞）。「更浅」仍保留在第一档，但它离纯白的余量太小 ——
悬停只能压到 ΔE 0.3–0.59，几乎看不出，所以那条路径加了护栏：步进自动收缩，宁可浅也不穿层。

深色侧的步长与浅色**解耦**（见上表 `darkLift`），不再按比例缩：
旧写法把 `-0.020×0.6` 夹成 `-0.004`，深色导轨与画布只剩 ΔE 0.49 —— 边界直接消失，
而同一档在浅色侧是 2.10。现在两侧都是 1.9–2.1，同一个档位在明暗两模式下强度一致。

## 文字着色（v0.8.0）

正文原来只给 0.004 的色度（近中性），视觉上就是「黑字 / 白字」。现在有第三行「文字着色」，
三档按倍率作用于**正文色度**（浅色 `textC` / 深色 `paperC`），底色不动，对比度仍由求解器兜底：

| 档位 | 倍率（浅 / 深） | 暖砂正文 | 暖砂深色正文 | 对比度 |
|---|---|---|---|---|
| 中性 | 1 / 1 | `#12110f` | `#f3efe5` | 17.21 / 14.97 |
| **跟随（默认）** | 1.8 / 1.5 | `#12110d` | `#f5efe0` | 17.23 / 14.98 |
| 浓一些 | 2.6 / 2.2 | `#13110c` | `#f8efd9` | 17.20 / 15.01 |

靛蓝的「浓一些」深正文是 `#e9effd`（冷白透蓝）、苔绿是 `#e3f5e6`（灰绿白）。
三档在承诺面上的对比度全部不变（三级 4.63–4.68、深正文 14.40–15.01），
**加的是色味不是明度**，所以不会牺牲可读性。

**深色侧三档是「温度」而不是「强度」**：近白处的色度台阶受 sRGB 上限约束（L 0.953 时蓝最多
0.0235、黄 0.038），三档之间的 ΔE 只有 0.4–1.0，切换时是"细看才分得出"的差别。
`paperC` 就是按这个约束定的：暖砂 0.014（跟随 36% 可用色域）、靛蓝 0.009（60%）、
苔绿 0.0125（23%），三套的「浓一些」都还在色域内、不会被 8-bit 夹取。
早期版本 `paperC` 给到 0.015–0.016，靛蓝的中性档就已经吃掉 66% 色域、「浓一些」请求 0.033
实得 0.0241 —— 第三档等于不存在。

次级与三级文字跟着同一档位走，但它们的色度基数更低（`midC 0.006`），所以仍是「带一点味的灰」，
不会变成彩色字 —— 正文的层级靠明度建立，不靠饱和度。

## 右侧栏可以跟左栏同色（v0.9.0）

宿主的三栏布局里，左右是不对称的：

| 列 | 背景 |
|---|---|
| 左栏 `.sidebarCol` | `var(--dsw-specific-sidebar-fill)` |
| 中栏 `.centerCol` / 整框 `.frame` | `var(--dsw-alias-bg-base)` |
| **右栏 `.rightbarCol`** | **没有背景**，露出的是 frame 的 `bg-base` = 会话区画布色 |

所以右栏永远和中间一样，v0.9.0 起设置页多一行「右侧栏底色：**同左栏** / 跟随画布」（默认同左栏）：

```css
/* 插件注入到 <head>，用官方同一套 data-plugin-css 标记 */
[data-rightbar-col]{background:var(--dsh-rightbar-fill,var(--dsw-alias-bg-base))}
[data-rightbar-fullscreen] [data-rightbar-col]{background:var(--dsw-alias-bg-base)}
```

- 钩子是 `data-rightbar-col` —— ui-layout 里 `RightbarColumn` 上的**语义属性**，不是哈希类名，
  宿主升级时不会跟着变；
- 颜色不经硬编码：token 层只给一个 `--dsh-rightbar-fill`，值是 `var(--dsw-specific-sidebar-fill)`
  或 `var(--dsw-alias-bg-base)`，所以它会自动跟着「左侧栏底色」三档一起变；
- 全屏右栏时退回画布色 —— 那时右栏就是整块内容区，染成侧栏色会像只剩一条侧栏。

## 滚动条等中性组件（v0.10.0）

宿主的四条滚动条 token 全指向 `neutral` 色阶：

| token | 浅色 | 深色 |
|---|---|---|
| `--dsw-alias-scrollbar-bg-l1 / l2` | `neutral-200` | `neutral-700 / 600` |
| `--dsw-alias-scrollbar-hover-l1 / l2` | `neutral-300` | `neutral-600 / 550` |

我本来就在染那条色阶，但它的色度只有 0.006 —— 肉眼看仍是灰。所以 v0.10.0 起设置页多一行
「**滚动条：中性 / 跟随 / 强调**」（默认跟随），**只抬色度、明度完全沿用宿主**：

| 档位 | 暖砂（浅 / 深） |
|---|---|
| 中性 | 不覆盖，走宿主中性色阶 |
| 跟随 | `#e2dac8` / `#423c2d`（配色色相，色度 0.026） |
| 强调 | `#f9d1ba` / `#533420`（强调色色相，色度 0.055） |

因为明度没动，滚动条与背景的明暗关系不变，不会出现"滚动条比内容还抢眼"。

黑白配色没有色相可跟随，那一行的说明文字会自己变成「当前是黑白配色，没有色相可跟随」。

**本来就跟随配色的中性组件**：边框（用色阶两端的墨/纸做 alpha）、分隔线、骨架屏、菜单表面、
`interactive-bg-*` 悬停层、`bg-document-selection`（选择高亮）、`markdown-code-segment-*`。
**故意不跟**：遮罩 `bg-mask-*`（保持中性黑）、代码 diff 的红绿、`state-error/warn` 语义色。

## 对话条目 / 正文的文字着色（v0.12.0 重新标定）

左栏的**会话条目**（标题、描述、时间戳）与正文用的是同一组 token ——
`label-primary` / `-secondary` / `-tertiary` → 色阶 `1000 / 700 / 600`（深色 `50 / 300 / 400`），
所以「文字着色」那一行同时管它们，不存在“正文变了、条目没变”。

v0.8.0 那版三档**实际是失效的**：实测 ΔE 只有 0.35–1.66，而并排色块的 JND ≈ 2 —— 看不见。
原因是物理限制：浅色模式正文落在近黑区（OKLab L≈0.19），那里 sRGB 色域极窄，
只加色度到 ΔE 1.6 就顶到 8-bit 量化上限。

v0.12.0 因此给文字着色加了**明度**这一维（`textLift`），把正文从近黑抬到能显出颜色的位置：

| 档位 | textScale / paperScale / textLift | 标题 ΔE（暖砂 / 靛蓝 / 苔绿） | 正文对比度 |
|---|---|---|---|
| 中性 | 1 / 1 / 0 | 0 / 0 / 0 | 17.2–17.3 |
| **跟随（默认）** | 2.2 / 1.8 / +0.030 | **2.77 / 3.15 / 3.25** | 16.2–16.3 |
| 浓一些 | 3.6 / 3.0 / +0.065 | **6.41 / 6.68 / 6.79** | 14.9–16.3 |

落色（暖砂）：中性 `#12110f` → 跟随 `#191713` → 浓一些 `#231f18`；
深色正文 `#f3efe5` → `#f6efdd` → `#fbeed0`。次级与三级文字仍比标题淡一档 ——
层级靠明度建立，着色只做「温度」，不把描述行也染色。

MIN_MAIN 从 15.5 放宽到 12：给“带色正文”留出明度空间，仍远高于 AAA 的 7:1。

## 交互态

内置的交互态是蓝灰墨（`#263148`）与冷灰写死的，配色一换就露馅。已按配色重算，
alpha **浅色与内置一致、深色压到 0.6 倍**（见下）：

| token | 内置 | 暖砂（浅 / 深） |
|---|---|---|
| `interactive-bg-hover` | `#2631480f` | `#12110d0f` / `#f5efe00d` |
| `interactive-bg-active` | `#2631481a` | `#12110d1a` / `#f5efe017` |
| `interactive-bg-hover-accent` | 无（自定） | `#12110d24` / `#f5efe024` |
| `menu-surface-fill` | `#f8f9fa94` / `#43454a73` | `#f5efe094` / `#46454173` |
| `button-tool-bar-hover` | `#54555799` | `#57555199` |

**为什么深色 alpha 要压**：深色叠的是近白纸色，8% 的纸色在 L 0.22 上抬起的明度，约等于 6% 的墨色
在 L 0.93 上压下的两倍。旧值（`0.08 / 0.14 / 0.24`）实测深色 hover / active / accent
ΔE `7.05 / 12.19 / 20.08`，是浅色（`3.92 / 6.76 / 9.51`）的 1.8–2.1 倍 —— 深色下悬停一行会「闪」，
按下像换了一块面。收到 `0.05 / 0.09 / 0.14` 后是 `4.6 / 7.9 / 12.2`，两个模式的手感对齐。

本来就跟（官方是 `var()` 引用）：`interactive-bg-hover-solid`、`button-ghost-active-*`、
`button-primary-hover`、滚动条、`markdown-code-segment-*`、`bg-document-selection`、`state-business-*`（焦点环）。
不跟的：`interactive-bg-hover-danger`（红）、`bg-mask-*`（遮罩中性黑）、代码 diff 红绿。

## 为什么不用「注册新主题」

`ctx.theme.register()` 注册的是**一个 colorScheme 固定的主题**，一套配色只能一个 id；要做
「同一套配色各自适配明暗」就得注册两个 id + 自己盯 `prefers-color-scheme` 反复 `setTheme()`，
还会撞三个官方约束（自定义 id 不持久化、`adopt()` 回灌覆盖、dispose 生效中的主题会重置 preference）。
所以用更弱的 `ctx.theme.overrideTokens(source, tokens)`：明暗归官方「外观」，插件只换色。

```
dsh plugin --profile desktop add "E:\Documents\deepseek-harness\default-workspace\dsh-theme-palette"
```

## 结构

| 文件 | 作用 |
|---|---|
| `client.js` | 客户端：OKLCH 引擎 + `overrideTokens` 覆盖层 + `settings.section` 页面 |
| `index.js` | Host 半边，空实现 |

早先它自带一套旧引擎，报表和上线不是同一套。

## 调参

```js
{ id: 'warm', label: '暖砂', desc: '米白 + 棕调', tinted: true,
  hue: 88, lightC: 0.024, midC: 0.006, textC: 0.004,     // 灰阶：色相 + 三档色度
  darkC: 0.014, darkLift: 0.026, paperC: 0.014,          // 深色：层色度 / 明度错位 / 正文色度
  accentHue: 52.4, accentC: 0.101, accentL: 0.58,        // 强调：色相 / 色度 / 基准档明度
  accentScale: 1.0 }                                     // 整条强调色阶的明度倍率（保持 1.0）
```

换强调色只改这三个数（`accentHue` / `accentC` / `accentL`），色阶其余档、深色侧强调、
卡片预览色、`info` 按钮、焦点环全部自动跟随；链接会自己派生一条够 AA 的（见 §品牌基准色与链接）。
把目标颜色换成 OKLCH 的现成方法：`toOklch('#a9683e')` → `[0.5799, 0.1012, 52.3]`，
分别填进 `accentL` / `accentC` / `accentHue`，再用 `node palette-dev.mjs` 核 `500` 是否逐位对上
（8-bit 取整偶尔差 1，把 `accentHue` 挪 0.1–0.5° 即可）。

深色三个数是**每套单独定的，不能抄**：

| 套 | darkC | 占可用色域 | darkLift | 深底 L | paperC |
|---|---|---|---|---|---|
| 暖砂 | 0.014 | 30% | 0.026 | 0.223 | 0.014 |
| 靛蓝 | 0.028 | 19% | 0.032 | 0.227 | 0.009 |
| 苔绿 | 0.015 | 24% | 0.042 | 0.239 | 0.0125 |

调参时先看**占比**再看数值：`darkC` 除以该 L 与色相下的 sRGB 可用色度上限，落在 20–30% 是
「有色但不脏」；低于 15% 会读成灰（蓝色最容易踩），高于 40% 开始读成泥（黄色最容易踩）。

加一套配色就往 `SCHEMES` 里加一条，卡片、覆盖层、对比度求解、报表全自动。
文字着色倍率在 `TEXT_MODES` 里（`textScale` 管浅色正文、`paperScale` 管深色正文）。
`accentScale` 保持 1.0 —— 它是乘性的，压低会把强调色浅端（`deepseek-50/100/200`）整条压塌，
而这几个正是宿主的「选中态软底」。

## 已知边界

- 悬浮层 `150` 上三级文字 4.22–4.27，不在承诺内（见上）。
- **暖砂基准色上的白字只有 4.43**（靛蓝 5.77、苔绿 5.01）。宿主把 `deepseek-500` 当
  `button-info-fill` 的填充色，若那里写白字，4.43 差 0.07 到 AA —— 这是 `#a9683e` 这个颜色
  本身的属性（赭石色偏亮），不是参数能修的。要过就把该按钮的文字换成深端（`deepseek-900`
  那侧）或改 15px 以下的字号策略。
- **基准色与链接色是两条线**：`--dsw-static-deepseek-500` 是设计标准值（填充/焦点环/预览色），
  `--dsw-alias-link` 是派生色。任何新加的 UI 若把 500 当**文字**用，都会踩 AA（暖砂 3.40）。
- 深色最亮的承载面 `800`（layer-3 / module）上链接是 4.65（0.8.2 后 4.64–4.70），只比阈值高
  0.02–0.08 —— 那是求解器靶点决定的（`MIN_LINK_DARK = 4.62`）。**以后若再抬 `darkLift`，
  必须同步抬 `MIN_LINK_DARK`**，否则链接会在 AA 线上横跳。
- `paperC` 只服务 `50` 号色，而 `50` 号在浅色侧同时是菜单表面的基色（`menu-surface-fill`）：
  `paperScale` 任何放大都会顺带把浅色菜单染深。0.8.1 把 `paperC` 降下来后这个耦合的影响变小了，
  但结构还在。真要解耦得让 `50` 号不再兼任「深色正文」与「浅色表面」。
- 深色三档文字色拉不开（ΔE 0.4–1.0）是 sRGB 近白天花板决定的物理限制，
  不是参数没调对 —— 别为拉档差去抬 `paperScale`。
- 黑白配色完全走宿主值，含宿主本身的 3.71 / 4.23（AA 未达标）。要修需要给 mono 建一条
  走引擎的色阶，属于观感变更，另行确认。
- `blue` 与 `deepseek` 两条色阶被染到同一色相，信息态与品牌色不可分；需要时给 `blue` 单独的色度系数。
- 渲染效果未在真实 GUI 里验证过（本机没有可控浏览器会话）。
